# 公告管理弹窗与界面优化审计

## 原页面问题

- 新增公告使用独立路由和整页表单，用户需要离开列表上下文。
- 表单在宽屏上横向铺满，基础设置、正文和图片之间缺少清晰的步骤层级。
- 列表筛选、记录总数和公告更新时间的视觉优先级不明确。

## 调整方案

- 列表页内使用宽屏 `el-dialog` 创建公告，关闭遮罩点击，避免误操作丢失内容。
- 公告编辑器支持嵌入式模式；新增弹窗和独立编辑页复用同一套校验、上传与保存逻辑。
- 表单分为基础信息、公告正文、正文图片三段，并提供步骤编号、辅助说明和粘性操作区。
- `/announcements/new` 保留兼容，重定向到列表并自动打开新增弹窗。
- 列表增加页面图标、记录总数、标题更新时间副文本和发布状态视觉标记。

## 安全与数据边界

- 没有修改公告 API、权限或数据结构。
- 只有 `config:write` 权限可看到新增、编辑和删除操作。
- 弹窗取消和关闭不会提交公告；创建成功后关闭弹窗并重新加载第一页。
