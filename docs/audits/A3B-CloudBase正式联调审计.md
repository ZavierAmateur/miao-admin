# A3B CloudBase 正式联调审计

## 审计目标

- 将管理后台直接联调已部署的 CloudBase 云托管服务 `miao-travel-wechat`，确认 A1-A3 管理接口可被真实页面使用。
- 将 V1 后台收缩为单管理员、低频内部工具，不引入管理员管理、复杂角色配置、通知中心和占位数据页。
- 保持管理接口只经 `/admin/v1/*` 访问，浏览器不直连数据库，也不在前端保存长期令牌。

## 实施范围

- 导航只保留“玩家管理”，根路由直接进入玩家列表。
- 保留管理员登录/退出、玩家列表、玩家详情、微信资料、存档诊断、回滚、封禁和解封页面。
- 移除仪表盘、接口状态和接口文档的前端路由入口；这些能力不属于 V1 简易后台。
- 存档诊断不再展示后端内部 hash，页面只显示运营判断所需的 revision、版本、时间、大小和字段差异。

## 本地联调方案

- 新增 `npm run dev:cloud`，由 Vite 同源代理把 `/admin` 请求转发到 CloudBase 云托管正式服务。
- `.env.cloud` 只保存公开服务地址和本地代理开关，不包含管理员账号、密码、Cookie 或 CloudBase API Key。
- 代理为本地回环地址覆写已获后端允许的 `Origin`，避免浏览器跨域。
- 仅在本地 HTTP 调试时移除响应 Cookie 的 `Secure` 属性；`HttpOnly` 与 `SameSite=Strict` 保持不变。外部部署必须使用 HTTPS，同源反向代理不得移除 `Secure`。

## 风险边界

- 本次对正式服务只执行登录、读取和退出；未对真实玩家执行回档、封禁或解封。
- 当前方案用于开发机内部访问，不等于管理后台已发布到公网。
- 后续若对外部署管理后台，需要单独配置 HTTPS、同源代理、访问控制和后端允许来源。
