# A6C 用户管理命名与空列表诊断审计

## 审计日期

2026-09-20

## 发现

- 后台界面仍使用“玩家管理”，与产品希望统一使用“用户管理”的命名不一致。
- `npm run dev` 默认代理到本机 `127.0.0.1:3000`；内存后端没有微信 CloudBase 中的游戏用户，因此列表会正常返回空数组。
- `npm run dev:cloud` 才连接已部署的 `miao-travel-wechat`。
- 管理员账号保存于 `admin_users`，游戏用户保存于 `players`；登录后台不会自动创建游戏用户。
- 游戏用户只有成功完成小游戏平台登录后才会写入 `players`。
- 使用后端现有微信 CloudBase 配置完成只读核对：`players` 当前有 1 条微信游戏用户记录，未输出用户 ID、平台身份、昵称、头像或密钥。因此本次空列表不是云数据库无数据，优先检查后台是否仍由普通 `npm run dev` 或旧进程提供服务。

## 执行范围

- 将当前用户可见的“玩家管理/玩家详情”等文案统一改为“用户管理/用户详情”。
- 保留稳定的 `/players` 前端路径、`/admin/v1/players` 后端接口、`playerId` 字段和权限名，不做破坏性契约改名。
- 本地环境在列表页显示明确警告；空列表区分别解释本地内存数据、CloudBase 游戏用户和管理员账号的区别。
- README 增加空列表排查说明。

## 后端影响

无。接口、数据库集合、权限和字段均不变化。
