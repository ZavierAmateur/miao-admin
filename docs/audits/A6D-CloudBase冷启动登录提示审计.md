# A6D CloudBase 冷启动登录提示审计

## 审计日期

2026-09-20

## 问题

- CloudBase Run 最小实例数为 0，冷启动期间管理员会话请求可能超时或返回 503。
- 路由会带 `unavailable=1` 跳转登录页，这是合理的降级。
- 原会话仓储在非 401/403 错误时仍把 `sessionChecked` 标记为完成，导致服务恢复后无法重新检查。
- 登录页只根据地址栏参数显示错误，参数不会自动清除，因此线上服务恢复后仍持续显示“管理服务暂时不可用”。

## 线上核对

- `/health` 返回 HTTP 200。
- 未携带管理员 Cookie 的 `/admin/v1/auth/me` 返回预期 HTTP 401 `ADMIN_AUTH_REQUIRED`。
- 响应允许 `http://127.0.0.1:5173` Origin，说明管理员认证、服务访问和 CORS 当前正常。

## 执行范围

- 非鉴权类连接错误不再锁死会话检查状态。
- 登录页进入不可用状态后自动重新探测服务。
- 服务恢复后清除 `unavailable=1` 和红色提示；已有有效会话时回到原页面。
- 仍不可用时保留“重试连接”按钮。
- 账号密码错误继续显示真实登录错误，不误报为服务不可用。
